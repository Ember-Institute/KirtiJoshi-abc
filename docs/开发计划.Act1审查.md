## 0. V0 的真实缺陷：两个轴被混为一谈

V0 反复强调两条禁令——**禁止 `sorry`** 和 **禁止自定义 `axiom`**——并把它们当作严谨性的代理指标。问题在于形式化有两个彼此独立的轴：

| 轴 | 含义 | 谁来检验 |
| --- | --- | --- |
| **陈述能力**（statement capability） | 载体是否富到能把目标命题**写出来** | 忠实度审计 + 非空洞性测试 |
| **证明能力**（proof capability） | 是否已有**证明项** | `#print axioms` / sorry 清单 |

V0 为了回避第二个轴上的欠债，把**第一个轴也一起削弱了**。`AST₀` 之所以空洞，不是因为作者不知道该怎么写，而是因为把假设写弱是让证明义务消失的最省力方式。于是得到一个"陈述已退化、证明已完成"的产物：它在两个轴上都自称达标，实际上在第一个轴上已经失去了内容。

### 0.1 关键事实：审计原语的方向是反的

`#print axioms foo` 输出的是 `foo` 的**证明项**传递依赖的公理集（`Lean.collectAxioms`）。定理自身的**假设**位于**类型**中，**不属于公理集**。因此：

```lean
theorem cor312 (D : ASTData) (h₁ : AdelicThetaLink D) (h₂ : ThetaLiftLog D)
    (h₃ : PacketCollationHull D) (h₄ : VolumeTransfer D) : Corollary312 D := by ...
#print axioms cor312   -- 只输出 propext / Classical.choice / Quot.sound
```

`AdelicThetaLink D` **不会**出现在输出里。V0 §4.2 与 §6 P8 要求

> `#print axioms JoshiTeich.abc_of_cor312` 只显示 Lean 基础公理和**明确传入的外部结构**

后半句在 Lean 里做不到：**传入的外部结构永远不显示**。

反过来：

```lean
theorem adelicThetaLink (D : ASTData) : AdelicThetaLink D := by sorry
#print axioms adelicThetaLink   -- 输出含 sorryAx
```

`sorryAx` 会出现，并沿依赖链传播到最终定理。

**结论**：V0 的审计原语**对空洞化是盲的，对 `sorry` 是敏感的**。因此"禁 `sorry`、容忍空洞"恰好把审计信号优化到了错误方向——

> **让产物变"干净"的唯一手段，就是让它变空。**

这正是当前 475 行工程的状态：`#print axioms` 干净，`lake build` 通过，而 `AST₀` 几乎不含算术内容。

### 0.2 这与 Act1 的目的直接冲突

Act1 的目的是**澄清公众疑虑**。公众疑虑的焦点是"**输入假设是否可接受**"，而不是"推导是否正确"——推导部分本来就不难，参考工程已经证明它可拆成有限任务。

空洞化让推导变得平凡正确，同时让假设变得**不可见**。也就是说，空洞化不只是"不够严谨"，它**恰好摧毁了 Act1 唯一要交付的东西**。

V0 把 `sorry` 当成道德失败来规避；而一个关于"3.12 需要哪些假设"的计划本质上是一次**记账**——你需要看见欠债，而不是把欠债藏进假设的措辞里。

## 1. V1 的四条原则

**P1　陈述必须忠实。** 载体必须富到能**陈述**目标命题，即使不能证明它。能陈述 ≠ 能证明，这两个能力必须解耦。`sorry` 正是解耦工具。

**P2　空洞必须显式。** 未完成的部分用 `sorry` 标记并登记，**不允许**通过削弱假设来消除证明义务。

**P3　推导必须完整。** Act1 的推导层**零 `sorry`**。这是"澄清公众疑虑"的产物：假设全部在签名中可见，推导本身没有任何缺口。

**P4　审计必须能看见缺口。** `warn.sorry = true`，并维护 `SORRY_LEDGER.md`。审计输出中出现 `sorryAx` 是**正常且期望**的状态，它是有意义的进度信号，而不是需要消灭的污点。

一句话对照：

> V0：用弱假设换取干净的 `#print axioms`。
> V1：用 `sorry` 换取忠实的陈述，让 `#print axioms` 如实报出缺口。

## 2. 新的层次结构

```text
Act0/Statements/        ← 原"A1 之前"的全部义务，逐条变成 sorry 的 Lean 定理
  Carriers.lean           载体：必须富到能陈述目标（基于 mathlib 真实对象）
  Places.lean             数域、素位、局部域、归一化赋值
  Different.lean          different / conductor / Tate divisor
  Untilt.lean             untilt、tilt、Frobenius
  Arithmeticoid.lean      holomorphoid / arithmeticoid
  Obligations.lean        每条 source-id 一个命名定理，proof = sorry
        ↓ 挑选极少数作为
Act1/Public/            ← 零 sorry。这是给公众看的产物
  MinimalAST.lean         MinimalAST：可信、非空洞、可枚举
  Accepted.lean           少量"公认假设"，显式命名的 Prop
  Corollary312.lean       从 MinimalAST + Accepted 推出 3.12，推导完整
  Assembled.lean          cor312_assembled：把 gap 变成机器可见的 sorryAx
  Nontriviality.lean      AST/IUT 非平凡差异见证
        ↓
Act2/Completion/        ← 逐个填掉 Act0 的 sorry，然后继续主界 / Vojta / abc
```

依赖方向仍然是单向的：`Act0 → Act1 → Act2`，`Act1` 不得导入 `Act2`。

### 2.1 Act1 必须用显式形参，不得调用 Act0 的 sorry 定理

这是一个容易踩的坑。如果 `cor312` 直接调用 `Act0.adelicThetaLink`（其证明是 `sorry`），那么 `#print axioms cor312` 会含 `sorryAx`，Act1 就失去了"审计干净"这一唯一卖点。

因此**必须**分两个定理：

```lean
-- Act1/Corollary312.lean —— 零 sorry，假设全部在签名中
theorem cor312 (D : MinimalASTData)
    (h₁ : AdelicThetaLink D) (h₂ : ThetaLiftLog D)
    (h₃ : PacketCollationHull D) (h₄ : VolumeTransfer D) :
    Corollary312 D := by
  ...

-- Act0/Obligations.lean —— 这就是"欠债"本身
theorem JT_ATS_III_adelicThetaLink (D : MinimalASTData) : AdelicThetaLink D := by
  sorry

-- Act1/Assembled.lean —— 把欠债变成机器可见的信号
theorem cor312_assembled (D : MinimalASTData) : Corollary312 D :=
  cor312 D (JT_ATS_III_adelicThetaLink D) (JT_ATS_III_thetaLiftLog D)
           (JT_ATS_III_packetCollationHull D) (JT_ATS_III_volumeTransfer D)

#print axioms cor312_assembled   -- 含 sorryAx ⇒ 缺口可见
#print axioms cor312             -- 仅基础公理 ⇒ 推导完整
```

两条审计输出各司其职：

- `cor312` 的干净输出 + 签名中列出的四个假设 = **给数学界看的交付物**：`3.12` 恰好需要这四条，推导无缺口。
- `cor312_assembled` 的 `sorryAx` = **给工程看的欠债表**。Act2 每填掉一个 `sorry`，`sorryAx` 自动从输出中消失。**进度是可观测的，且无需人工记账。**

## 3. `sorry` 政策细则

### 3.1 允许范围

| 位置 | `sorry` | 说明 |
| --- | --- | --- |
| `Act0/Statements/` | **允许** | 未建成的数学与库的全部缺口 |
| `Act1/Public/` | **禁止** | 推导层必须完整；假设走形参 |
| `Act2/Completion/` | **禁止** | 每完成一项就删掉 Act0 对应的 `sorry` |
| `Audit/` | **禁止** | 测试与检查文件不得引入新缺口 |

配置：`lakefile.toml` 增加 `warn.sorry = true`。
**注意**：V0 §2.2 要求 `warn.sorry = false`，这与 V1 的政策直接冲突，必须修改。把 `sorry` 设为静默，同时声称禁止 `sorry`，等于让唯一能看见缺口的机制闭嘴。

### 3.2 每条 `sorry` 的登记要求

1. 定理名自描述，形如 `JT_ATS_III_adelicThetaLink`（`source-id` 的连字符换成下划线）。
2. 文件头注释写明：`source-id`、来源 TeX 位置、陈述忠实度、依赖的其它义务。
3. 在 `SORRY_LEDGER.md` 中占一行：`source-id | 定理名 | 文件 | 依赖 | 忠实度 | 归属（Act2.x） | 状态`。

### 3.3 计数与单调性

- 度量：`grep -rc "sorry" Act0/` 的总数，以及 `#print axioms cor312_assembled` 中出现 `sorryAx` 这一事实。
- 规则：**`sorry` 计数不得增加**。允许把一条 `sorry` 替换为更强的忠实陈述（若发现原陈述太弱），但必须在 `SORRY_LEDGER.md` 记录变更理由。
- 这条规则是 V1 对抗"空洞化棘轮"的对应物：V0 的棘轮是**悄悄削弱假设**，V1 明确禁止；V1 允许的唯一棘轮是**把陈述改得更忠实**，并且要求留痕。

## 4. `MinimalAST` 替换 `AST₀` 的设计要求

`AST₀` 应予删除，或降级为 `MinimalAST` 中的一个普通字段。新载体的验收标准：

### 4.1 必须基于 mathlib 真实对象

| 当前（空洞） | 应改为 |
| --- | --- |
| `PlaceData.valuation : K → ℤ` | 基于 `AbsoluteValue K ℝ` 或 `Valuation K Γ₀`（mathlib 已有 17 个 `Valuation` 文件） |
| `ossPlaces : Finset ℕ` + `place : ℕ → PlaceData K` | `Finset (AbsoluteValue K ℝ)` 或等价的素位类型 |
| `residueDegree : ℕ`（无约束） | 由 `NumberField` + 局部化推出（mathlib 有 `NumberField`、`DedekindDomain`） |
| `height : K → ℝ`（无约束） | mathlib 高度 API，若无则显式接口并列入 Act2 义务 |

**注意**：mathlib 完全没有 Berkovich(0)、Fargues–Fontaine(0)、Anabelian(0)、Frobenioid(0)、Vojta(0)；`Mathlib/RingTheory/Perfectoid/` 仅 387 行，且 `PreTilt.untilt` 的注释明确写"不是 untilt **函子**"。这些缺口**正是 `Act0` 的 `sorry` 该待的地方**——而不是被 `AST₀` 的弱字段掩盖。

### 4.2 陈述能力测试（新的硬性验收）

载体合格的判据是：**能写出 `Corollary312` 的忠实版本**，至少包含

- theta-pilot 区域与 `−|log(Θ)|` 的结构；
- `CΘ ≥ −1`（即 `−|log(Θ)| = CΘ·|log(q)|` 的形态）；
- different 与 conductor 的项；
- height 项；
- 归一化与 procession 长度。

当前 `Carriers.lean` **无法**陈述以上任何一项，因此按此标准不合格。这与"能不能证明"无关——只与"能不能写出来"有关。

同时：`Corollary312` 在 `SOURCE_LEDGER.md` 中的 `fidelity` 列必须从当前的 `shadow` 改为 `exact`（或至少 `weakened` 并逐项列出差异）。参考工程 `refer/iut` 的 `Iut/Cor312/Statement.lean` 已给出可效仿的免责声明范式：明确写出"本形式化不得读作已发表的 Corollary 3.12"。

### 4.3 非空洞性测试（机械化）

对 `MinimalAST`、`FirstAxiom`、`AdelicThetaLink`、`ThetaLiftLog`、`PacketCollationHull`、`VolumeTransfer`、`Corollary312` 每一项**同时**提供：

- 一个**满足**它的模型，且该模型**不退化**；
- 一个**违反**它的模型。

违反模型的存在即证明该陈述不是恒真式；满足模型的存在即证明假设组不矛盾。二者合起来把"契约是否只是 `Corollary312` 的改写"从主观判断变成**可编译的检查**——这是唯一能机械化对抗空洞化的手段。

**现有反例**：`Audit/FoundationAudit.lean` 的 `toyAST` 取 `qNorm ≡ 1`，故 `log 1 = 0`，`Corollary312` 在该模型中退化为 `0 ≤ 0`。它证明了 `AST₀` 非空，但**没有**证明 `Corollary312` 非退化，因此按新标准不合格。

## 6. 对 Act1 目的的重新表述（建议写入文档开头）

> Act1 不证明 Corollary 3.12。Act1 给出的是：**一份恰好四条假设的清单，以及从这四条假设到 Corollary 3.12 的无缺口推导。**
>
> 每一条假设都有独立的 `source-id`、独立的数学含义、以及一个满足它的非退化模型和一个违反它的模型。推导本身不含 `sorry`，因此 `#print axioms cor312` 只输出 Lean 基础公理。
>
> 未被建成的数学（perfectoid、FF、Berkovich、anabelian）不以弱假设的形式隐藏，而以 `sorry` 的形式显式列在 `Act0/Statements/` 中，并登记在 `SORRY_LEDGER.md`。`#print axioms cor312_assembled` 会显示 `sorryAx`——**那是欠债表，不是缺陷。**

这个表述把"澄清公众疑虑"从一句口号变成了一个可审计的产物：**争论的焦点被精确定位到四条假设上，而不是散落在 128 个 label 的措辞里。**

## 7. 本文件的诚实边界

- 本文件是**设计与计划修订**，不是 Lean 代码变更。撰写环境**没有可用的 Lean 工具链**（Windows 侧无 `lean`/`lake`/`elan`，`wsl.exe` 被安全策略拦截），因此文中所有 Lean 片段均为**未编译的示意代码**，其语法与可编译性尚未验证。
- §0.1 关于 `#print axioms` 不报告定理假设的论断，依据是 `Lean.collectAxioms` 作用于**证明项**而非**类型**；在本环境中无法编译验证，但这是 Lean 的既定行为，建议在实际环境中用一段最小代码确认后再据以修订 V0。
- §1 的 P4、§2.1 的双定理设计、§3.3 的单调性规则是本次修订中**新增的、需要实际验证**的机制。
- 落地顺序建议：先做修订清单 #11–#13（现存错误）、再做 #1–#2（配置与政策）、然后 #4–#6（载体与忠实陈述）、最后 #7–#9（Act1 推导与 ledger）。#3、#10 是文档修订，可随时进行。
