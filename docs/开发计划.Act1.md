# JoshiTeich Act1：Arithmetic Teichmüller Spaces 的公开证明包

日期：2026-10-04

Act1 的目标是给出一个小而完整、可以独立审计的证明包。它不声称已经完成
Arithmetic Teichmüller Spaces 的全部数学，也不把 IUT 参考工程中的未证明接口当成
定理。它要完成的是：在一组明确、非计算性的 `Prop` 假设下，展示 Arithmetic
Teichmüller Spaces 与 IUT 的非平凡区别，并从这些假设推出 Joshi 版本的
Corollary 3.12。

Act1 依赖 Act2.Foundation 提供的载体、定义和第一组假设；Act2.Completion 再负责
证明这些假设以及完成 Corollary 3.12 之后的数论链。三者必须保持无循环依赖。

## 1. 逻辑结构

```text
Act2.Foundation
  ├─ 数域、素位、赋值、高度的载体
  ├─ ASTData 和 AST₀ : Prop
  ├─ JoshiTeich 版本的 theta、packet、hull、volume 记号
  └─ 可搬运的基础代码
          ↓
Act1.Public
  ├─ FirstAxiom : Prop
  ├─ AST₀ → FirstAxiom
  ├─ FirstAxiom + A₁ + A₂ + A₃ + A₄ → Corollary312
  └─ AST/IUT 非平凡差异的具体模型
          ↓
Act2.Completion
  ├─ 实际 JoshiTeich 数学 → AST₀
  ├─ Corollary312 → 主界 → Vojta → strong abc → abc
  └─ 其余证明义务
```

Act1 的依赖方向是单向的：

```text
Act2.Foundation → Act1.Public
Act2.Foundation → Act2.Completion
Act1.Public      → Act2.Completion
```

`Act2.Completion` 可以使用 Act1 的定理，但 Act1 不能导入 Completion。这样
“从 AST₀ 得到 Corollary 3.12”和“Act2 证明 AST₀”不会形成循环。

## 2. 工程和信任边界

- [ ] Act1 使用独立的 `JoshiTeich` 命名空间。
- [ ] Act1 不从 `refer/iut` 导入任何 Lean 模块；参考工程只用于逐文件搬运代码和核对 API。
- [ ] 搬运 Apache-2.0 代码时保留原版权、许可证和来源；每个搬运文件登记原路径、原提交和改写范围。
- [ ] Act1 不声明项目自定义的 Lean `axiom`、`sorry`、`admit` 或隐藏的 `opaque` 证明。
- [ ] 所谓“公理”全部实现为参数化的 `Prop` 定义或 `Prop` 结构字段。
- [ ] Act1 的公共定理使用显式输入，不通过全局实例或隐式常量携带数学结论。
- [ ] `#print axioms` 只允许出现 Lean 基础公理、明确选择的标准数学公理以及定理参数本身。

Lean 中的结构应采用下面的分工：

```lean
structure ASTData : Type where
  -- 数域、素位、untilt、theta 和 packet 的载体

def AST₀ (D : ASTData) : Prop :=
  -- 第一组公开假设，只包含性质

def FirstAxiom (D : ASTData) : Prop :=
  -- Corollary 3.12 证明真正需要的第一接口
```

需要被下游计算的域、函数、映射、有限集和范数必须放在 `ASTData : Type` 或其他
数据载体中；它们的性质放在 `Prop` 中。不能把一个需要实际使用的函数藏在
`∃ f, ...` 的命题里，再要求下游从中计算 `f`。

## 3. AST₀ 的设计标准

AST₀ 是 Act1 的第一个输入。它应该表达数学界熟悉的结构性质，而不是直接表达
Corollary 3.12。每个字段都必须满足以下条件：

- [ ] 字段是有限、清楚的局部或范畴性质。
- [ ] 字段不含 `Corollary312`、`lhs ≤ rhs` 或其等价改写。
- [ ] 字段不直接断言 theta-volume 的全局下界。
- [ ] 字段不直接断言 Mochizuki 的 anabelian 重构结论。
- [ ] 可以给出一个具体非空模型，说明 AST₀ 不是矛盾假设。
- [ ] 可以解释该字段在 Arithmetic Teichmüller Spaces 中的数学来源。
- [ ] 可以在 Act2.Completion 中单独证明，或者明确标记为尚未解决的研究义务。

“Scholze 和 Stix 不会反对”不能作为可机械验证的标准。Act1 采用可审计的替代
标准：假设的定义、范围、模型、与 Corollary 3.12 的距离以及尚未证明的部分都
公开记录。是否接受这些假设仍属于数学评议。

## 4. Corollary 3.12 之间的中间契约

Act1 插入四个核心契约。它们既对应 Joshi III 的证明链，也对应参考工程中已经
分开的 theta、container、hull 和 log-volume 模块。

这些契约在 Act1 中是显式的、彼此独立的 `Prop` 输入。`FirstAxiom` 不自动推出
`A₁`–`A₄`；Act1 只证明“给定 `FirstAxiom` 和四个契约即可得到 Corollary 3.12”。
`Act2.Completion` 必须分别证明 `FirstAxiom`、`A₁`、`A₂`、`A₃` 和 `A₄`，之后才
能把条件性定理拼合为具体的 JoshiTeich 结果。

### `FirstAxiom`：第一公理

`FirstAxiom D` 是 Act1 的第一个公开接口。它不直接给出 Corollary 3.12，而是给出
构造 adelic theta-link 所需的最小结构。它通常包含：

- [ ] 固定的 holomorphoid/arithmeticoid 载体和有限 procession；
- [ ] untilt、Frobenius、局部赋值及其兼容映射；
- [ ] Tate 参数和 theta 参数的索引数据；
- [ ] 所有有限索引集、归一化和非退化条件。

Act1 必须证明：

```lean
theorem firstAxiom_of_AST₀ (h : AST₀ D) : FirstAxiom D := by
  ...
```

### `A₁`：AdelicThetaLink

`AdelicThetaLink D` 对应 III 的 `th:adelic-theta-link` 和
`th:hyperplane-theta-lnk`。它只声明局部到全局所需的 theta-link 性质：

- [ ] `q ↦ q^(j²)` 的 valuation scaling；
- [ ] Galois/Frobenius 作用的相容性；
- [ ] 乘积公式或周期映射的精确类型；
- [ ] 各局部坐标的归一化关系。

它不能包含 theta-pilot 的体积下界。

### `A₂`：ThetaLiftLog

`ThetaLiftLog D` 对应 III 的 Teichmüller lift、log-shell 和 `θ_M/θ_J` 构造：

- [ ] theta 值在指定周期环或有限维替代环中的提升；
- [ ] 提升范数与原 theta 值的关系；
- [ ] `log` 在指定范围内保持所需的绝对值；
- [ ] lift 对 Galois/Frobenius 作用的稳定性。

对于无限维 Fréchet 环、完整的 period ring 和 `H¹_e/H¹_f` 识别，Act1 可以先保留
显式 `Prop` 接口，但必须把它们列为 Act2.Completion 的证明义务。

### `A₃`：PacketCollationHull

`PacketCollationHull D` 对应 procession、tensor packet、collation 和
holomorphic hull：

- [ ] theta-pilot 元组能够组成有限 packet；
- [ ] packet 的局部数据可以 collation 到统一载体；
- [ ] theta-pilot 区域满足 hull admissibility；
- [ ] hull 在指定 hull region 类中最小；
- [ ] 包含关系和 Galois/Frobenius 作用保持相容。

这一契约应使用显式的数据载体。不能只给出“存在某个 packet”，而不让下游访问
packet 的索引、区域和体积。

### `A₄`：VolumeTransfer

`VolumeTransfer D` 是从局部 theta-pilot 数据到归一化 log-volume 的最后一个数学
接口：

- [ ] 局部 packet 体积满足所需单调性；
- [ ] cross-norm 或有限乘积公式可以应用；
- [ ] procession 平均与全局归一化相容；
- [ ] 局部界可以有限求和；
- [ ] 所得表达式仍然保留 `q`、theta-pilot 和 hull 的独立记号。

Act1 应把最后的实数整理写成普通定理：

```lean
theorem cor312_of_volumeTransfer
    (h₀ : FirstAxiom D)
    (h₁ : AdelicThetaLink D)
    (h₂ : ThetaLiftLog D)
    (h₃ : PacketCollationHull D)
    (h₄ : VolumeTransfer D) :
    Corollary312 D := by
  ...
```

如果 `VolumeTransfer` 的陈述已经等价于 `Corollary312 D`，则应删除该契约并把它
改成定理；不能通过换一个名字增加假设层数。

## 7. 完成标准

Act1 只有在以下条件同时满足时才算完成：

- [ ] AST₀、FirstAxiom、A₁、A₂、A₃、A₄ 和 Corollary 3.12 的类型已冻结；
- [ ] `AST₀ → FirstAxiom` 有完整 proof term；
- [ ] `FirstAxiom + A₁ + A₂ + A₃ + A₄ → Corollary312` 的每一步都有独立定理；
- [ ] 至少有一个非空 AST 模型；
- [ ] 有一个明确的 AST/IUT 非平凡差异见证；
- [ ] 没有项目自定义 Lean `axiom`、`sorry` 或隐藏证明；
- [ ] `lake build`、源代码审计、许可证审计和 `#print axioms` 均通过；
- [ ] 文档明确区分“已证明”“条件性输入”“原型”和“Act2 待完成义务”。

Act1 的最终产物是一个条件性但完整的公开定理包：它清楚展示 AST 与 IUT 的
非平凡差异，并清楚展示哪些性质足以推出 Corollary 3.12。Act2 负责把这些性质
从具体 JoshiTeich 数学中构造出来。
