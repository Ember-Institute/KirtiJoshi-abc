# JoshiTeich 版 `abc` 猜想：Lean 形式化开发计划 V0

日期：2026-10-04

这是一份**独立的 JoshiTeich 形式化计划**。目标是把 Joshi 的 Arithmetic
Teichmüller Spaces 路线改写成可审计的 Lean 定理链，最后得到 `abc` 的明确
条件和结论。源论文都是 preliminary version；本计划不把论文中的宣称自动当成
Lean 定理。

## 1. 阅读范围和证明主线

已阅读 `refer/JoshiTeich/` 中全部六个 `index-` 文件：

- [Arithmetic Holomorphic Structures](../refer/JoshiTeich/index-Arithmetic%20Holomorphic%20Structures.md)：untilt、算术全纯结构、算术 Teichmüller 空间和 tempered 基本群的标记拷贝。
- [Arithmetic Teichmüller Spaces I](../refer/JoshiTeich/index-Arithmetic%20Teichmuller%20Spaces%201.md)：Berkovich/tempered 基本群不变性、算术全纯结构、Galois 上同调汇集和 adelic 空间。
- [Arithmetic Teichmüller Spaces II](../refer/JoshiTeich/index-Arithmetic%20Teichmuller%20Spaces%202.md)：Fargues–Fontaine 曲线、Tate 椭圆曲线、`q ↦ q^{j²}`、Teichmüller lift、theta-pilot locus 和局部 Corollary 3.12 原型。
- [Arithmetic Teichmüller Spaces II½](../refer/JoshiTeich/index-Arithmetic%20Teichmuller%20Spaces%202.5.md)：arithmeticoid、adelic FF 曲线、全局 Frobenius、height 稳定化、differents/conductors 和几何 Szpiro 原型。
- [Arithmetic Teichmüller Spaces III](../refer/JoshiTeich/index-Arithmetic%20Teichmuller%20Spaces%203.md)：holomorphoid、Initial Theta-Data、adelic theta-link、log-shell、`θ_M/θ_J`、Mochizuki Corollary 3.12 和 Rosetta Stone。
- [Arithmetic Teichmüller Spaces IV](../refer/JoshiTeich/index-Arithmetic%20Teichmuller%20Spaces%204.md)：从 Initial Theta-Data、两个主界、Vojta 不等式到 `abc` 的最终链。

计划采用下面的依赖图：

```text
数域/素位/赋值/高度
        ↓
arithmeticoid + holomorphoid + untilt/FF 接口
        ↓
Tate 曲线 + q-除子 + Initial Theta-Data
        ↓
adelic theta-link → log-shell → theta-pilot → Corollary 3.12
        ↓
不同/导子主界 + theta log-volume 主界
        ↓
Vojta 不等式（Mochizuki IV / Genl 形式）
        ↓
strong abc → classical abc
```

IV 中的核心结果链是
`th:existence → th:theta-upper-bound → th:main-bound → th:main-dioph-thm → th:main-thm → abc`；
III 中给出 Corollary 3.12 的前置链
`th:adelic-theta-link → th:thetam-construction → th:moccor-Mochizuki-form1 →
th:moccor-Mochizuki-form2 → cor:cor312`。

工程现在明确分为两个 Act 和三个层次，Act1 的详细清单见
[开发计划.Act1.md](./开发计划.Act1.md)：

- `Act2.Foundation`：形式化 Act1 之前的载体、定义和第一组公开假设 `AST₀`，并搬运可复用的基础代码。
- `Act1.Public`：从 `AST₀` 得到 `FirstAxiom`；以 `FirstAxiom` 和四个显式的 `Prop` 契约 `AdelicThetaLink`、`ThetaLiftLog`、`PacketCollationHull`、`VolumeTransfer` 为输入推出 Corollary 3.12，并展示 AST/IUT 的非平凡差异。Act1 不声称这些契约由 `FirstAxiom` 自动推出。
- `Act2.Completion`：证明 `AST₀`，完成 Act1 之后的主界、Vojta 和 `abc` 义务。

依赖方向固定为 `Act2.Foundation → Act1.Public → Act2.Completion`，同时
`Act2.Completion` 可以直接使用 `Act2.Foundation`。Act1 不得导入 Completion。

所有 Lean 源码、Lake 配置、构建和测试都在 `ArithmeticTeichmullerSpaces/` 中进行。
仓库根目录的 `docs/` 和 `refer/` 只保存计划、来源和参考材料，不作为 Lean 工程
目录。

## 3. “证明都是可计数的吗？”

可以把**工作项目**做成可计数清单，但不能把“可编号”解释成“每一项都已有可行证明”。具体分三层：

1. **可枚举的来源条目**：六个索引文件给出有限的 label、定义、定理、引理和推论；每一项都能绑定唯一的 `source-id`。
2. **可枚举的 Lean 任务**：每个 `source-id` 可拆成数据载体、假设字段、辅助引理、主定理、测试和文献核验项；Lean 的声明本身是有限字符串，因此可机械编号、追踪和审计。
3. **不可由编号保证的数学可证性**：perfectoid/tilting、Fargues–Fontaine 全局几何、Berkovich tempered 基本群、anabelian 存在性、无限维 Fréchet 张量积和全局 Corollary 3.12 仍可能需要新的数学或新的库。它们只能标为“接口/待研究”，不能填成 `sorry` 后宣称完成。

因此 V0 把任务分为：

- `P`（proved）：在本工程内有完整 Lean 证明；
- `C`（conditional）：定理已形式化，但深层结果作为普通参数传入；
- `S`（specification）：只有类型正确的定义和命题，没有证明；
- `B`（blocked）：需要先解决新的数学或库问题。

现有 IUT 代码显示，`Corollary312Variant → ABC` 的**推导部分**可以拆成有限、可验证的任务；但 JoshiTeich 路线要把 `Corollary312Variant` 本身从 `S` 提升为 `P`，仍不是几个空白证明的机械填充。

按 Act1/Act2 划分后，计数单位变为：`AST₀`、`FirstAxiom`、四个中间
`Prop` 契约、Corollary 3.12、非平凡性见证，以及 Act2 的各个实现定理。每一项
都可以有唯一 `source-id`、独立的 Lean 声明和明确的证明状态；可计数不等于已经
证明。
