# 三语自然语言读回原则

## 1. 适用范围与基本要求

本规范适用于本工程在 Prove2Me 中使用的证明节点、定义节点及其英文、简体中文、日语说明。当前工程目录为 `/home/admin-wsl/Coq/abc`，平台适配工作区为其中的 `prove2me_workspace/`。目录改名不改变声明、来源或证明状态。

依据工作区保存的 `mission_captain.md` 与 `mission_auditor.md`，Prove2Me 支持并推荐为每个草稿定理、定义附上独立读回；这是推荐配置，不能表述成平台一律强制。引用既有平台内容的 `reference` 条目不接收新的读回。本工程以每个可配置读回的节点均具备三语材料为实施目标。

三语必须对应同一份形式声明，保持相同的对象、量词、前提、结论和依赖关系。翻译不能补全尚未形式化的数学内容，也不能把开放节点描述成已证明节点。本文只规定文字与来源处理；节点拆分、独立工程原则、证明边界及构建纪律仍遵守既有开发计划和 `AGENTS.md`。

## 2. 每个节点的三类文字

| 文字类别 | 回答的问题 | 依据与边界 |
| --- | --- | --- |
| 论文来源说明 | 论文原文说了什么，本节点取自何处？ | 使用指定作者的原始论文，附原文段落及准确定位；说明适配范围。 |
| 形式声明读回 | 当前代码实际断言或定义了什么？ | 独立审读者只依据形式代码及审读规则生成，不接触论文说明和作者意图。 |
| 直观解释 | 核心概念大致表示什么，为什么引入？ | 明确标注“直观解释（非严格）”，在读回完成后另行撰写，不代替正式陈述。 |

三类文字必须有明确标识，不能把论文引文放进盲审读回，假称审读者从代码中独立读出了它。英文的论文来源段落遵守第 4 节，三语形式读回遵守第 3 节。论文来源说明与形式读回出现差异时，分别保留两者并指出差异，不通过润色把差异抹去。

一个节点含有多个来源时，按具体结论分别归属。代码来自哪个工程、数学陈述来自哪篇论文、适配后实际证明了什么，是三个需要分别记录的事实。

## 3. 三语共有的数学精度

### 3.1 完整陈述

每个声明应有可独立理解的读回单元，完整交代符号含义。可使用公式、分段和并列条件提高可读性，但不能只写标题或摘要。

必须覆盖以下内容：

- 所有显式、隐式参数，全称与存在量词，以及类型类提供的数学假设。
- 各对象的取值范围、映射的定义域与陪域，以及必要的结构和相容条件。
- 全部前提、结论及逻辑方向，包括等价与蕴含、存在与唯一存在、严格与非严格不等式。
- 量词的先后次序与常数的依赖范围。例如“对每个正数，存在一个常数，使得对所有三元组……”不能改写成“对每个三元组存在一个常数……”。
- 限制条件、例外集、归一化、所取商或等价关系，以及构造是否唯一、是否依赖选择。
- 非标准定义的实际含义。不能仅复述自定义谓词的名称，使其内部尚未证明的条件消失。
- 代码允许的退化情形，包括零、空集、自然数减法的截断、除以零的约定及可能无法满足的前提；按具体声明说明，不机械加入无关情形。

声明引用的局部定义、实例或记号若影响语义，必须纳入审读材料。缺少必要定义时补齐材料后再读回，不能根据声明名或论文背景猜测其含义。

### 3.2 陈述、证明与归约

读回说明命题的内容，不自行宣判形式化是否忠实、数学论证是否成立。证明状态在单独的状态说明中如实表达：草稿占位、对子结论的条件归约、完整证明不得混用。含占位证明的声明能够编译，不等于该命题已经证明；组合定理也不能省略其接收的子结论。

引用论文中的“定理”或“推论”时，保留论文编号与作者归属；这种引用本身不构成本工程已闭合证明链的证据。

### 3.3 三语一致性

三语逐声明、逐条件对齐。可以调整句序和语法以符合目标语言，但必须保持量词作用域与依赖关系。符号重命名必须给出对应关系；同一节点不能在不同语言中悄悄采用不同的高度、测度、常数或对象。

原文引文、术语解释和读回均使用可渲染的数学记号。引文中的公式按原文核实；读回中的公式以代码语义为准。两者不一致时，不能擅自择一覆盖另一份文字。

## 4. 英文：原始论文与段落引用

### 4.1 来源归属

从 `refer/iut` 移植或依据该参考工程形成的内容，其英文论文来源段落使用望月新一的原始论文。参考工程的注释、说明文件和声明名称只能帮助定位，不能替代论文原文段落。

与 Kirti Joshi 有关的证明，其英文论文来源段落只引用 Kirti Joshi 的原始论文，不使用望月新一论文替代。即使 Joshi 原文讨论望月新一的结果，也先准确引用 Joshi 本人的表述；不能用另一作者的相近结论替换正在适配的结论。

混合来源的节点必须拆开说明。例如，移植构件的来源说明引用望月新一，Joshi 适配结论的来源说明引用 Joshi；二者之间的比较或桥接结论单独列明，不因名称相近就宣称已经等价。无法从指定作者原文找到依据的部分标记为“来源待核实”，不得编造引文或改用另一作者填补。

本工程自行构造、原文没有逐字对应的辅助引理，应说明它是本地辅助结论，并引用所服务的原文段落及实际依赖。不得把本地推导冒充成作者原文。

### 4.2 段落引用的最小资料

每项实质性来源说明至少保存：

- 作者、论文完整标题、卷次或系列编号、版本或日期。
- 官方原文链接、本地原文路径；下载文件还应记录取得日期与文件摘要，避免版本混淆。
- 章节、定义／定理／推论编号及分项；同时记录印刷页码与文件页序，二者不同须注明。
- 足以涵盖当前结论及其限定条件的英文原文段落。省略部分用省略标记表示，不拼接出原文没有的主张。
- 原文符号与本地符号的对应、本节点覆盖的部分，以及额外适配、未覆盖部分或待证明的桥接。

原文引用使用块引文，编辑者说明另起一段。不得把改写、翻译、机器抽取修复或本地补充放在引号内冒充逐字原文。对于公式、上标、重音符号和换行造成的歧义，回到论文页面核实。

可使用以下定位格式；占位项必须在正式交付前补齐：

> 作者：《论文标题》，版本／日期，第 X 节，定理或推论 Y（分项 Z），印刷第 P 页，文件第 Q 页。官方链接：……；本地文件：……。
>
> 此处逐字引用已核实的英文原文段落及必要公式。

随后说明本地声明名、符号对应、覆盖范围和适配差异。论文出处与代码移植出处分别保留；代码出处还需遵守既有许可证、原提交及独立工程记录要求。

### 4.3 原文取得与存放

优先核对 `refer/Mochizuki/` 中已有资料。现有文字抽取件可用于检索，但不能代替有歧义处的原版页面核对。材料不足以支持引用时，直接从 [望月新一官方网站](https://www.kurims.kyoto-u.ac.jp/~motizuki/) 找到对应论文的原始便携式文档文件，下载到 `refer/Mochizuki/`。

下载时保留完整论文与版本信息，不用二手介绍代替原文，不覆盖仍被节点引用的旧版本。记录最终下载地址；确认所得文件确为论文而非错误页面。只补取当前节点所需的材料，不因制定本规范批量下载论文。

Joshi 来源也应核对作者提供的原始论文版本，并在现有来源记录中保存准确位置；不把它归入望月新一的作者目录。论文版本更新后重新核对相关编号、公式和引用，不只更换链接。

### 4.4 英文读回的文风

独立读回使用清楚、完整的数学英语，解释符号，保留逻辑强度，不堆砌代码语法。论文原文的特殊措辞保留在来源引文中；审读者不能为了模仿论文文风而补入代码没有表达的含义。

## 5. 简体中文：术语、姓名与自然表达

### 5.1 数学术语完整翻译

正文中的数学术语使用完整的简体中文译名，不以外文缩写代替。例如写“主理想整环”，不写“PID”。常见外文缩写也不能因为熟悉就直接沿用。

例外限于人名组合导致全称过于冗长的惯用缩写，例如“ZFC 集合论”“BRST 量子化”。不将这项例外扩展到一般对象、性质或算法名称。

源文件路径、声明标识符、平台字段、文献原题、原文引文和术语对照表中的原词允许保留原样，用于准确定位；它们不能取代中文叙述中的术语翻译。数学公式中的变量和符号依原意保留。

### 5.2 人名命名的概念

中国人的姓名使用汉字。日本作者有可确认的汉字姓名时也使用汉字，例如 `Shinichi Mochizuki` 写作“望月新一”；没有可确认的汉字姓名时可以使用假名，不要求使用或附列拉丁字母姓名，也不猜造汉字姓名。这项日本姓名规则也适用于人名命名的概念，例如写“中山引理”。

其他人的姓名使用通用拉丁字母拼写，保留扩充字母与音符，例如 `ß`、`þ`、`ð`、`é`、`è`、`ê`。不能为方便检索而在正文中去掉这些字符。

本规范采用以下写法：陈类、Lie 代数、中山引理、Gauß 绝妙定理、Calabi–丘流形、Euclid 几何、Pontryagin 对偶、Poincaré 群。

西文中由人名加后缀形成的形容词或派生词，译成中文时去掉后缀，恢复人名本身：

| 西文形式 | 中文写法 |
| --- | --- |
| Abelian group | Abel 群 |
| abelianization | Abel 化 |
| Cartesian product | Descartes 积 |
| Riemannian geometry | Riemann 几何 |

中外姓名组合分别处理，例如“Calabi–丘流形”。同一人的姓名采用一致拼写；文献原题、逐字引文、源代码标识与检索字段保留原样。英文论文署名仍按原文引用，不为统一中文姓名而修改原始引文。日本作者在日语正文中也优先采用可确认的汉字姓名，其余日语姓名处理遵守第 6 节。

### 5.3 未知译名与占位规则

确有未知或尚未确定的中文译名时，先核对本工程已经采用的术语及可靠用例。仍无法确定，则向用户给出候选译名及各自含义，请用户选择；不能自行把猜测写成确定译名。

每次询问列明英文原词、作者及具体出处、所指对象、候选译名和可能混淆的概念。有合理备选时给出二至三个候选；只有一个可行候选时直说，不凑造选项。与当前节点无关的未知术语不预先批量询问。

通用的关键术语与姓名登记在[三语术语名词关键对照](三语术语名词关键对照.md)，区分“用户提议”“建议候选”与“用户已定稿”。用户征求译名意见不等于已确认译名；本工程自定译名也不能标作通行译名。

等待答复期间继续处理不依赖该译名的内容。没有收到回复时，在正文保留 `【译名待定：术语编号】`，并在对照表中保存原词、候选与询问状态，在节点现有本地记录中保存术语编号和出现位置；不能把沉默当作同意。该中文版本可以作为待完善草稿保存，但不能标记为术语已定稿。

用户确认后统一替换全部对应占位符，并核查是否混入别的概念。占位符只表示译名待定，不能遮盖定义缺失、来源不明或证明尚未完成。

### 5.4 汉语句法与直观解释

优先采用符合汉语习惯的主谓结构，不照搬外文被动句和长串后置修饰语。例如：

- 避免：“一个域是一个集合，其上加减乘除四则运算被定义，且具有像实数或有理数上的对应运算那样的行为。”
- 采用：“域是带有加减乘除四则运算的集合，这些运算满足实数、有理数的四则运算那样的性质。”严格定义仍须另外交代除数非零等条件。

支柱级核心概念在首次出现或专门的概念节点中给出尽可能直观的非严格意义，再给出精确陈述和来源。直观解释必须显式标注，不用比喻替代假设或证明。

例如可写：“直观解释（非严格）：Yoneda 引理大致说明，范畴中的对象可以由它到所有其他对象的态射及这些态射随目标变化的方式来识别。例如，若两个对象到任意目标的态射集构成自然同构的函子，则这两个对象同构。”正式使用时附对应引理或推论的实际编号，不能保留虚构编号。

这个解释必须保留“自然”及态射随目标变化的相容性，不能缩成“态射集大小相同就同构”。采用从其他对象到该对象的对偶表述时，必须整体调整方向，不能混用两个方向。

## 6. 日语：百科文风与术语对应

### 6.1 文风

采用日语维基百科式的中立、说明性常体，通常使用「である」体，避免口语、敬体混用、宣传性评价和对证明的辩护。首先交代对象及定义，再说明性质；必要时给出标明为直观说明的解释。

使用自然的日语数学句法、通行数学记号和日语标点。首次出现的专门术语按需要注明英文原词；已经确定的译名随后保持一致。日本作者有可确认的汉字姓名时使用汉字，例如“望月新一”；没有时可以使用假名，不要求附拉丁字母姓名。其他姓名与人名定理采用日语数学写作的惯用形式。

### 6.2 望月新一术语参考

优先从 `refer/日语翻译参考/` 核对望月新一论文的关键术语。目前该目录含：

- `宇宙際 Teichm¨uller 理論入門.pdf`
- `続・宇宙際 Teichm¨uller 理論入門.pdf`
- `遠アーベル幾何学の進展.pdf`

上述名称按当前文件名列出，不据此认定文件名中的字符就是规范术语。采用译名时记录实际页码、原词和上下文；这些文件是日语术语参考，不能替代第 4 节要求的数学原始来源，也不能未经核实标作作者官方译本。

若日语百科文风要求翻译某个术语，而参考中没有，可按照同一领域的日语构词与既有译名直接类推。类推结果在术语记录中注明“类推”及依据，不能谎称出自参考文件。无需仅因采用类推法而暂停工作询问用户。

### 6.3 Kirti Joshi 术语的严格对应规则

必须先核对两位作者原文实际使用的英文词或完整术语，不能只凭概念相似性决定日语名称：

| 原文关系 | 日语处理 |
| --- | --- |
| Joshi 与望月新一使用同一个英文词或同一个完整英文术语 | 共用同一个日语词；必要时另加作者、对象或语境说明。 |
| Joshi 使用的英文词或完整术语与望月新一不同 | 另行命名，绝不因意义接近而共用同一个日语词。 |
| 尚未取得或核实其中一方的原文用词 | 保留日语译名待核实标记，不提前认定同词或异词。 |

同一个英文词得到同一个日语词，不表示两位作者定义的数学对象相同，更不表示其定理可以互换。不同英文词即使被一般词典视为同义词，本工程也保留不同日语名称。

对于多词术语，比较整个术语；共享一个组成词不能成为合并完整名称的理由。不同术语中的相同组成词可保持对应，但完整日语名称必须能够区分。原文仅有字体、排版换行或扫描识别差异时先核对页面；不能通过自行删去修饰词、展开缩写、替换同义词等操作，把不同用词强行视为相同。

若惯用译法会使两个不同英文词落入同一日语名称，采用不同的日语构词或可稳定区分的限定名称，并记录各自原词。不能在表中假设二者等价后再共用简称。

## 7. 独立审读、翻译与平台保存流程

1. **固定代码版本。** 确定节点标识、完整前置代码、形式声明及必要定义，记录内容摘要和依赖版本。不能只提交声明名让审读者猜测。
2. **独立盲审读回。** 使用全新上下文的独立 `gpt-6.1-sol` 子智能体，仅提供该节点的 Lean 代码、必要前置定义和 `mission_auditor.md`。不得提供非形式陈述、论文、任务宣传、预期结论或预先编好的三语来源段落。
3. **冻结原始读回。** 原样保存审读结果与实际审读模型。若材料不足则补充代码后重新审读；不让项目作者代写或润色成预期结论。原始审读通常采用平台要求的数学英语。
4. **制作中文与日语译文。** 翻译者使用冻结的读回及必要代码核对语义，按本规范处理术语。译文标明其来自哪份读回；翻译者不是原始独立审读者，不把三语译文伪称为三个独立审计结论。
5. **编写来源与直观说明。** 盲审读回冻结后，再附上第 4 节要求的原文段落、三语来源说明及单独标注的直观解释。发现差异时先定位代码、来源或翻译中的问题，不能把论文预期反灌进原始读回。
6. **逐项对照。** 检查三语的量词、前提、常数依赖、逻辑方向、非标准定义、退化情形与证明状态；确认所有术语占位符和来源缺口均明确可见。
7. **按实际字段保存。** 作者的来源及意图说明放在 `natural_language_statement` 等平台已支持的说明位置；`readback` 保存独立读回及有明确语言标签的译文，`readback_model` 填写实际独立审读模型。原始读回、翻译者及版本对应关系保存在本地现有节点记录中，不虚构平台专有三语字段。
8. **修改后更新。** 形式声明或影响其语义的前置代码、定义、实例发生改变时重新盲审，并重新对齐三语。只改译名或排版时保留原始读回，记录翻译修订；不得让旧读回为新代码作证。

上传前按届时的平台接口核实字段支持。三语内容在同一文字字段中保存时，使用明确语言标签与分隔，保持一个声明的三语对应，不另建三个数学节点。翻译说明不能混入原始读回段落。

文字使用 Markdown 与 KaTeX。通过结构化序列化生成请求：本地文字中的一个公式反斜杠，在 JSON 字符串编码中应正确转义；不能手工重复转义破坏公式。上传后回读核对保存内容、语言标签与渲染。

这套流程不改变既有平台操作授权。制定规范不等于已执行节点盲审、上传、人工确认或公开发布；文档编写本身不触发这些操作。

## 8. 记录与验收

通用关键术语与姓名集中维护在[三语术语名词关键对照](三语术语名词关键对照.md)，节点与代码版本的对应记录维护在 `prove2me_workspace/.local/` 既有节点资料中，不为本规范另增进度文档。每条术语记录至少包含：作者及原文词、概念语境、原文位置、中文译名或占位符、日语译名、日语参考位置或类推依据、用户确认状态；具体使用节点在节点资料中引用术语编号。英文相同但定义不同的情况保留各自语境，英文不同的情况不得合并成一条日语名称。

节点资料还应能追溯代码版本、原始独立读回、审读模型、三语修订和论文版本。对于同一节点，来源未核实、译名待定、待重新审读、证明开放是彼此独立的状态，不能用一个“已完成”覆盖它们。

每次交付三语材料时逐项核对：

- [ ] 三语对应当前同一份代码，全部量词、前提、结论及常数依赖一致。
- [ ] 原始读回由独立审读者盲写，完整保存，未混入来源引文或作者意图。
- [ ] 望月新一来源与 Joshi 来源按结论分清；原文段落、版本及定位均可核实。
- [ ] 本地辅助结论、适配差异和未证明桥接明确列出，没有冒充原文结论。
- [ ] 中文术语完整翻译，缩写例外受限，姓名、字符、后缀处理和汉语句法符合本规范。
- [ ] 未知中文译名已给候选并询问；无回复时仍有明确占位符，未冒称定稿。
- [ ] 日语采用百科文风；参考译名与类推译名可区分，同英文词共译、异英文词分译。
- [ ] 核心概念有标明非严格性质的直观解释，且不损失精确读回。
- [ ] 证明状态如实表达，平台字段、模型归属、数学渲染与回读结果一致。

仅编写或修订自然语言规范不需要编译 Lean 工程。若落实规范时改动形式代码，则按 `AGENTS.md` 经 MCP-CI 完成对应检查，不因文字审读而绕过原有构建与公理审计要求。
