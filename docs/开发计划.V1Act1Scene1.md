## 1. 当前边界和总体状态

当前 Prologue revision 为 `R5`。`Prologue/Core` 只提供载体、局部 Tate 参数法律、
非退化条件和局部 perfectoid bridge。2026-10-21 的边界修订
`JT-SCENE1-BOUNDARY-PRODUCER-CONTRACTS-20261021` 将以下命题从
`PrologueInputLaws` 抽出，改由 Scene1 producer 显式提供：

- `AdelicThetaLink`；
- `ThetaLiftLog`；
- `PacketCollationHull`；
- `VolumeTransfer`。

对应代码是 `Act1Scene1/ProducerContracts.lean` 和 `Act1Scene1/Boundary.lean`。
`Scene1Input.ofExplicit` 只是兼容包装器，不能作为真实 producer 的存在性证明。

Scene1 的真实生产链分为四阶段：

1. `InitialThetaGeometryProducer`：从 arithmetic/Tate seed 产生 `OrbicurveData`、
   `LocalThetaData` 和同一份 `InitialThetaData`；
2. `HolomorphoidSource`：产生 untilt、tilt、解析基点、Tate parameter family 和跨来源标记；
3. `H1eBKPeriodSource`：产生 H¹ₑ、crystalline、Bloch–Kato、period 和 log 比较；
4. `PaperCollationSource`：产生论文 representative、multiplicity、weight、theta locus
   和 `thetaVolume` 身份。

四阶段目前都没有无条件的真实 producer。它们必须以显式数据和 `Prop` 法律出现，
不能通过全局实例、`Prologue/Obligations` 或改名现有 actual carrier 来补齐。

## 4. 负面证据和路线排除

以下结论只排除列明的具体路线，不等于排除所有论文解释，也不等于证明论文命题错误。

### N1：actual contracting q-root 不能直接作为旧 theta base

`ThetaLogSignAudit.lean` 和 S1.321 证明：actual contracting q-root 的 norm 小于 1，
而旧 `AdelicThetaLink` 的 period/log/normalization 与 `VolumeTransfer` 共同强制
`logVolume ≥ 0`，所以不能把 q-root norm 直接装进旧 `thetaBase.norm`。这排除
“q-root = theta base”的装配路线；不排除另一个 theta lift、different untilt 或负对数
cost 解释。

### N2：signed Haar log-volume 不能直接填入旧 VolumeTransfer

actual ordinary-log hull 在正长度时的 signed Haar log-volume 严格为负，而旧 transfer
需要非负 packet/hull weight。S1.321 排除了直接等式；S1.322/S1.406 给出可保留路线：
使用 `-log(volume)` 的非负 actual cost，并由 cost producer 产生 transfer。该修复仍未
证明论文 `thetaVolume` 身份。

### N3：Joshi III 字面 Corollary 的 qLogTerm 存在符号冲突

S1.305 的 actual selected contracting q-root 证据显示，字面右端
`-∑ log |q_w^(1/(2ℓ))|` 在普通实数 log 下为正，而字面左端为非正；因此不能直接把
字面式当作当前 Lean target。用户决定暂按笔误处理（S1.332），但这只冻结临时解释，
不关闭 G1，也不允许无记录地反转符号或取 reciprocal。

### N4：ambient Kummer/unit carrier 不能改名为 H¹ₑ 或 BK

S1.403、S1.447–451 证明 actual continuous H¹、unit subspace、saturated Kummer carrier
和 normalized ordinary-log witness 的局部性质；S1.451 还证明 contracting q-root class
不在 normalized principal-unit class 的当前 ℚₚ 单生成空间。它们排除把 ambient unit
subspace、normalized class 或 q-root class 直接命名为论文 H¹ₑ/BK 的路线。它们不排除
通过真实 period/holomorphoid producer 得到另一种论文比较。

### N5：固定 completion factor orbit 不能替代跨 holomorphoid collation

actual factor automorphism、closure、hull 和 Haar monotonicity 已证明，但它们只作用在
同一 completion tensor carrier。Joshi III 的 Ind1–Ind3、不同 untilt、arithmeticoid 和
global collation 尚未出现。因而不能把 fixed-factor orbit identity 宣布为论文跨来源
collation 或 theta locus identity。

### N6：canonical finite carrier 不能自动成为论文 `V_p^oss`/`L'`

actual selected source、VBad、finite support 和 coefficient-weighted sum 已有精确会计，
但 S1.489–503 仍显示 representative defect、omitted mass、global degree 和 paper
weight 不能被简单除法消掉。不能把 finite equivalence、degree-one witness 或 selected
support 自动命名为论文处集、代表或无缺陷 paper sum。

### N7：参考工程不能提供缺失的真实 producer

`refer/iut` 的 `AnabelianExistence` 是显式条件接口；其已证明的 model existence 只适用于
`modelAG/modelTG`。参考工程没有当前项目所需的任意真实 `AG/TG`、holomorphoid marking、
H¹ₑ/BK comparison、Fréchet `B`/ρ-norm 和 paper collation 的联合 proof。不能通过移植
`thetaData`、改名 `PerfectoidBridgeLaws` 或调用 `Prologue/Obligations` 补齐生产者。

### N8：Prologue 四项 source law 不能被当作“显然合理假设”而结束证明

把 `AdelicThetaLink`、`ThetaLiftLog`、`PacketCollationHull`、`VolumeTransfer` 放在
Core 只会使 Scene1 条件性消费者通过；它不会证明这些命题来自真实数学输入。它们已经
移到 `Scene1ProducerLaws`，但真实 producer 义务仍开放。这是信任边界修正，不是数学
结论的负面证据。

## 5. 执行顺序

1. 先完成 G2 的 `InitialThetaGeometryProducer`，得到共同真实 `InitialThetaData` 和
   `orb/localData` 来源；没有它，后续局部结果只能保持 conditional。
2. 在同一对象上完成 holomorphoid、period、H¹ₑ/BK 和 Fréchet `B`/ρ-norm producer。
3. 完成 G3 的论文处集、representative、multiplicity 和 weighted carrier。
4. 完成 G1 的符号/归一化冻结，再做 G4 的 paper theta locus、volume 和最终 Corollary。
5. 最后执行窄目标构建、ImportAudit、Checks、Axioms、`git diff --check` 和一次用户要求的
   全图验收；通过后提交并推送，按用户要求暂停，不开始 Scene2。

## 6. 构建与审计规则

- 使用 CPU affinity `0-13`、`LEAN_NUM_THREADS=14`、Lean worker `-j1` 和现有热缓存启动构建，无论是冷构建还是热构建；
  不删除 `.lake/build`，不冷建 Mathlib。所有编译进程的总内存使用上限为100GiB, 超出则降低`LEAN_NUM_THREADS`，最低为1
- maxHeartbeats 第一次失败后执行以下自动优化流程：1. 进行所有显然可以执行的优化操作 2. 通过 show_term 得到证明项使用各种方法测量具体 tactic 的消耗，然后用证明项直接替换掉昂贵的 tactic. 3. maxHeartbeats 第一次失败设 1000000, 然后是 2000000, 4000000. 如果仍然无法通过，或者步骤(1)(2)无法降低 maxHeartbeats ,就将叶模块拆成小引理. 通过的交付条件为: 叶模块已在默认 maxHeartbeats 中通过，或者叶模块已经被拆分为充分小的小引理链并且 maxHeartbeats 提升收缩到单个声明或局部实例化。
- Scene1 禁止导入 `Prologue/Obligations`、Scene2、Act2 或隐藏全局输入。
- 导入 Mathlib 必须精确导入必要模块，不得进行和叶模块需求无关的 Mathlib 导入
- 每个 producer 输出必须有实际消费者；每个消费者字段必须能追溯到
  `SOURCE_LEDGER.md` 的来源和忠实度。
