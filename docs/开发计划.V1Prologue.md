# JoshiTeich V1 Prologue：有来源的基础设施和显式证明债务

日期：2026-10-04

## 1. 目的

Prologue 建立从 mathlib 到 `AdelicThetaLink` 的基础设施。它的目标不是假装完成
Arithmetic Teichmüller Spaces，而是确保生产者和消费者之间的中间定理已经有明确
数学含义，能够被下游实际使用，并且每个未完成构造都能在 Act2 中单独追踪和消除。

Prologue 不得通过弱化载体来消灭证明义务。一个空的 `K → ℤ`、任意的 `height`、
任意的 `qNorm` 或没有约束的有限索引集不能冒充相应的数域、赋值、height、theta
或 packet 数学对象。

## 2. 来源规则

Prologue 中的每个数据字段、命题字段和构造定理必须属于下列一种来源：

| 来源类别 | 允许内容 | 必须登记 |
| --- | --- | --- |
| `M` | mathlib 中已有的类型、定义和已证明定理 | mathlib 文件、版本和声明名 |
| `J` | JoshiTeich 论文中的对象、定义或定理陈述 | 论文、章节、TeX 行号或 source-id |
| `I` | IUT 参考工程中可直接复用的代码或 API | 原文件、提交、许可证、改写范围 |
| `D` | 由已有 `M/J/I` 内容组合出的本地定义或辅助引理 | 依赖的 source-id 和语义说明 |

没有来源的字段必须标为 `B`（blocked）或先补来源，不能直接写进载体。来源登记
不等于证明；论文中的声明仍需标为 specification、conditional 或 proved。

### 2.1 直接复制 IUT 的规则

只有同时满足以下条件，IUT 文件才可以作为无 `sorry` 的直接搬运：

- 在冻结的 Lean 和 mathlib 环境下独立编译；
- 源文件和传递依赖没有项目自定义 `axiom`、`sorry` 或 `admit`；
- 当前声明的类型和数学含义与原声明一致；
- 没有依赖未搬运的 `Iut.*`、`genl` 或其他隐含模块；
- 保留版权和 Apache-2.0 通知，并登记原提交和改写范围。

不满足这些条件时，不能用“参考工程已有证明”掩盖缺口。应建立忠实的命题接口，
把未完成构造登记为 Prologue 证明义务。

## 3. 数据和命题分层

需要被消费者访问的数据必须进入 `Type`：

```lean
structure AdelicThetaLinkData : Type where
  numberField : Type*
  places : Type*
  thetaPilot : Type*
  packet : Type*
  hull : Type*
  qParameter : numberField
  -- 其余可计算的映射和索引数据

structure AdelicThetaLink (D : AdelicThetaLinkData) : Prop where
  valuation_scaling : Prop
  frobenius_compatibility : Prop
  period_map : Prop
  normalization : Prop
```

这只是结构示意。实际字段必须来自 `M`、`J` 或 `I` 的可追溯陈述。不能写成
`∃ data, ...` 后要求 Scene1 从命题中计算 `data`。

`AdelicThetaLink` 不得包含 Corollary 3.12、theta-volume 全局下界，或与最终不等式
等价的字段。它应当描述局部到全局的 theta-link 结构：`q ↦ q^(j²)` 的 valuation
scaling、Galois/Frobenius 相容、周期映射和归一化关系。

## 4. Prologue 目录和导入边界

建议目录如下：

```text
Prologue/
  Mathlib/          -- mathlib 适配和已证明基础引理
  Arithmetic/       -- 数域、素位、赋值、different、conductor、height
  Perfectoid/       -- untilt、Frobenius、period ring 接口
  Theta/            -- Tate、Initial Theta-Data、theta-pilot 数据
  Interfaces/       -- 无 sorry 的载体和 Prop 契约
  Obligations/      -- 使用 sorry 的命名构造证明
  Audit/            -- 来源、模型、导入和 axiom 审计
```

`Act1Scene1` 和 `Act1Scene2` 只能导入 `Interfaces` 以及其中所需的无缺口基础模块。
它们不能导入 `Obligations`。`Obligations` 只供 Act2 在 Act1 闭合后使用。

## 5. `sorry` 政策

允许的形式是一个有来源的命名定理：

```lean
-- source-id: JT-ATS-III-adelic-theta-link
-- source: Arithmetic Teichmuller Spaces III, §...
-- fidelity: weakened, differences recorded in SOURCE_LEDGER.md
-- owner: Act2.Prologue.AdelicThetaLink
theorem build_adelicThetaLink
    (D : AdelicThetaLinkData) : AdelicThetaLink D := by
  sorry
```

禁止以下做法：

- 用 `sorry` 定义没有来源的载体字段；
- 用一个巨大 `sorry` 定理同时吞掉多个没有独立含义的接口；
- 用名称变化把 `Corollary312` 改称 `VolumeTransfer`；
- 在 Scene1 或 Scene2 调用上述构造定理；
- 以 `#print axioms` 干净作为接口忠实的证据。

每个证明债务在 `SORRY_LEDGER.md` 占一行，至少包含：

```text
source-id | 声明 | 文件 | 来源位置 | fidelity | 依赖 | Act2 归属 | 状态
```

## 6. 非退化验收

每个主要载体和接口必须通过以下检查：

- 至少一个满足模型，模型中 `q`、theta-pilot、packet、hull 和 log-volume 不全部退化为 1 或 0；
- 至少一个违反模型，说明该接口不是恒真命题；
- 下游 Scene1 的实际证明使用该接口的关键字段；
- 接口不包含目标定理或目标定理的等价改写；
- 每个字段都有来源和数学解释。

仅以 `qNorm ≡ 1`、`logVolume = 1` 的 toy 对象证明非空，不满足 Prologue 的非退化验收。

- [ ] Scene1/Scene2 可以只导入 `Interfaces`，不导入 `Obligations`；
- [ ] Prologue 还未完成时，不得开始 Act2 的实现。
