# JoshiTeich V1 Act1：两个无缺口的公开证明场景

日期：2026-10-04

Act1 分为 `Act1Scene1` 和 `Act1Scene2`。两个场景都禁止 `sorry`、自定义 `axiom`、
`admit` 和隐藏 `opaque` 证明。Prologue 的证明债务只能作为显式类型参数出现，不能
通过 Prologue 的 `sorry` 构造定理进入证明项。

## 0. 动态边界审计契约

### 0.1 目的和基线

在 Corollary 3.12 的精确形式尚未写入 Lean 之前，不能把 Prologue 的当前边界当成
最终的数学假设集。P0.17 建立的边界记为 `Prologue-R0`：它是一个可复核的基础设施
基线，不是对未来 3.12 需求的永久承诺。任何把声明加入 Prologue、从 Prologue 移出，
或在两者之间拆分的行为都必须产生一个新的边界修订记录，不能通过直接编辑旧结论
来改变信任边界。

边界移动必须同时记录两种负担：

- 晋升到 Prologue 可能减少 Scene1 的证明工作，但会增加对前置数学假设的信任负担；
- 从 Prologue 抽出并在 Scene1 实现可能增加当前证明工作，但会减少前置假设负担。

审计记录必须说明这两种负担的变化，不能只报告 Lean 文件变少或证明通过。

### 0.2 三层状态

动态边界使用三个状态层：

1. `Prologue/Core`：已接受的载体和无缺口的、来源明确的局部 `Prop` 契约。公开
   `Interfaces` 可以导入这一层。
2. `Prologue/Candidate`：为解释或尝试 3.12 而提出的候选声明。候选声明必须有来源
   和目标作用记录，但在审计决定前不得进入公开导入图，也不得成为 Scene1 的隐式
   参数。
3. `Scene1/Derived`：只服务于已形式化的 3.12、或由 Core 契约在 Scene1 中实际
   推出的命题。它必须以显式参数和完整 proof term 出现。

候选声明的状态只能是 `candidate`、`accepted`、`extracted`、`rejected` 或
`blocked`。`accepted` 才能晋升到 `Prologue/Core`；`extracted` 表示它已经从
Prologue 移出并由 Scene1 提供证明，不能仅表示换了文件名。

### 0.3 边界变更记录

每个变更使用唯一的 `change-id`，至少登记以下字段：

| 字段 | 要求 |
| --- | --- |
| `change-id`、旧/新 revision | 说明变更的唯一身份和边界前后版本 |
| `operation` | `promote`、`extract`、`split` 或 `reject` |
| `declaration` | Lean 声明、文件和公开名称 |
| `target-role` | 它在 3.12 中承担的确切局部作用；未知时标为 `blocked` |
| `statement` | 完整类型或命题，不接受只写名称或自然语言摘要 |
| `source-ids`、`fidelity` | `SOURCE_LEDGER.md` 中的来源和忠实度说明 |
| `proof-status`、owner | `proved`、`conditional`、`open` 或 `blocked`，以及负责阶段 |
| `model-evidence` | 联合满足模型、违反模型或模型义务的精确位置 |
| `dependency-effect` | 导入图、证明参数和下游消费者的变化 |
| `circularity/minimality` | 说明它不等价于 3.12，并说明删除或弱化后的影响 |
| `burden-delta` | Scene1 证明负担和前置信任负担各自如何变化 |
| `decision`、时间和审查者 | `accepted`、`extracted`、`rejected` 或继续阻塞的理由 |

变更记录采用追加方式保存。旧 revision 的记录和来源位置不得被覆盖，以便答辩时
重放每一次边界移动。

### 0.4 晋升到 Prologue 的验收条件

只有同时满足以下条件，候选声明才可以从 `Prologue/Candidate` 晋升到公开
`Prologue/Core`：

- 它是独立、可复用的局部数学事实，而不是 3.12 或其等价不等式的改名；
- 载体字段进入 `Type`，性质进入 `Prop`，且所有字段有来源和数学解释；
- 有至少一个共同满足模型；若构造尚未完成，必须有单独命名的证明债务和 owner；
- 有违反模型、弱化模型或明确的模型义务，证明该声明不是恒真命题；
- Scene1 的计划证明确实消费其关键字段，而不是只把它作为装饰参数；
- `#print axioms`、导入审计和 `sorry` ledger 不显示隐藏的构造依赖；
- 晋升不会把 `Corollary312`、目标体积下界或最终主界塞进 Prologue；
- 变更记录完整说明它减少了哪一部分证明工作，以及增加了什么信任负担。

### 0.5 从 Prologue 抽取到 Scene1 的验收条件

下列声明应优先考虑抽取，而不是继续扩大 Prologue：

- 只对 3.12 的量词、归一化、符号或定量下界有意义；
- 已经包含 theta-volume 下界、主界或与 3.12 等价的结论；
- 其证明需要 Scene1 才有的 packet/hull 组合或目标特有的中间量；
- 在 Prologue 中存在会掩盖真正数学困难的宽泛假设。

抽取必须同时满足：声明移出公开 Prologue，Scene1 以显式参数或局部定义接收它，
并提供无 `sorry` 的证明或单独的、可审计的条件性桥接。抽取不能以删除字段、改名
或把同一命题放入另一个结构的方式完成。

### 0.6 直到 3.12 形式化前的冻结规则

在 `Corollary312` 的完整 Lean 类型、量词、归一化和来源位置确定前：

- 只允许对来源明确的载体和目标独立的结构性局部法律进行 Core 修订；
- 任何新的定量下界、`q` 项、全局体积结论或目标特有归一化都必须留在 Candidate；
- Candidate 不得被 `Interfaces`、Scene1 或 Scene2 导入；
- 不得以“证明变得容易”为理由晋升候选声明；
- 形式化目标确定后，必须先完成一次边界复审，再开始 `cor312_of_scene1_data`；
- 若现有 Prologue 合约不足以推出目标，应优先记录失败模型和最小增量，而不是直接
  把目标结论加入前置假设。

### 0.7 不可破坏的不变量

任何边界 revision 都必须保持以下不变量：

- Prologue 不包含 `Corollary312` 或其等价改写；
- Scene1/Scene2 不通过全局实例、隐藏常量或 `Prologue/Obligations` 获得输入；
- 所有未证明内容仍有唯一 source-id、证明 owner 和状态；
- 生产者输出必须有实际消费者，消费者字段必须可追溯到来源；
- 边界移动不改变已证明定理的声明，只能增加显式参数、证明或审计记录；
- Act2 仍只能在 Act1 的目标和桥接全部闭合后开始。

## 1. Scene1：从完整 Scene1 数据到 Corollary 3.12

### 1.1 导入边界

Scene1 允许导入：

- Prologue 的数据载体；
- Prologue 的无缺口 `Prop` 契约定义；
- mathlib 的标准定理；
- Scene1 自己的辅助引理。

任何 `Prologue/Candidate` 声明都不在允许列表中。候选晋升或抽取必须先有第 0 节的
边界变更记录；Scene1 只能依赖变更决定为 `accepted` 的 Core 声明或自己已经证明的
Derived 命题。

Scene1 禁止导入：

- `Prologue/Obligations`；
- 任何返回 `AdelicThetaLink`、`ThetaLiftLog`、`PacketCollationHull` 或
  `VolumeTransfer` 的 `sorry` 构造子；
- `Act1Scene2` 或 Act2。

### 1.2 公共接口

当前公共入口是一个条件性的装配定理。它消费已经构造好的体积、q-family、归一化和
packet/hull 账本；它不声称这些对象由 `AdelicThetaLink` 单独推出：

```lean
theorem cor312_of_scene1_data
    (D : Corollary312Scene1Data) :
    Corollary312 p D.target := by
  ...
```

q-pilot 路径使用更强的显式结构 `Corollary312Scene1QPilotData`，其中 `source` 必须是
`IutQPilotSource`；本地 q-pilot 由该来源和 q-family compatibility 派生。其余字段是
`TateOrderNormCompatibility`、`Corollary312QPilotSourceNormalization` 和
`Corollary312QPilotSourceIndexBridge`，入口名称为
`cor312_of_scene1_qPilot_data`。审计代码现在有一个显式 `ℚ,(2)` arithmetic carrier，
使用实际的 `inertDeg/[K:ℚ]` 权重并闭合这些字段的类型和等式。该 carrier 仍不是来自真实
`InitialThetaData/TateFamily`。新增的 `IutQPilotSource` 现在还必须显式保存
`badPlacesOver` 的有限性、Tate 参数、q-order 及其正性/非零性，并给出它们与本地
link/Tate carrier 的等式，以及 raw `uniformizerNorm` 等于 canonical completion uniformizer
范数的证书。该证书现在进一步拆成逐处 chosen completion element、
`Arithmetic.IsCompletionUniformizer` 证书，以及 chosen element 范数等式；canonical
completion norm 等式由这些字段和已证明的 valuation/norm 定理派生。适配器由该 raw
certificate 推出 residue-degree 对数律，并接入独立的
degree-normalized q-factor bridge；它不再从该证书派生 raw q-pilot 的目标形状归一化。
`AdmissiblePrimeData.q_order_coprime` 也已绑定到该 source，并可投影为每个 `(p,w)`
pair 的互素条件；source-index grouping 不再需要从来源之外另行提交这项证明。
Prologue/Core 现在还提供对任意显式 `Valued.v x = exp (-1)` completion 元素的同一
范数/对数律；这可以被真实 chosen uniformizer 消费，但不替代其 `TateFamily` 来源证明。
raw `Corollary312QPilotSourceNormalization` 现在是 `Corollary312Scene1QPilotData` 的显式
Scene1 条件。仅凭 norm-bad 元素生成来源的构造器已经退休。
当前 `ℚ,(2)` 见证只检查显式审计载体。真实来源和论文中的 `V_p^oss` 构造仍是开放证明
义务。

另有一个必须单独关闭的归一化义务：`iut` 的 `QPilotInputs.qPilot` 使用
`inertDeg / [K : ℚ]`，而当前 `AdelicThetaLinkData.qNorm` 是 mathlib 有限处的原始范数。
当前 source adapter 只提供 raw completion-norm certificate；raw-to-degree-normalized
的逐项桥已经独立存在，但 q-pilot 到 raw 3.12 q-factor 的归一化仍必须由 Scene1 显式
提供。raw/normalized 路径在目标形式审查前不能合并，也不能把任一条件路径称为真实
IUT 数值模型。

当前已增加一个不改变目标命题的候选适配器
`Corollary312DegreeNormalizedSourceQFactor`。它把现有 raw q-factor 的对数除以
`[K : ℚ]`，并有独立定理证明该关系；在额外的 raw uniformizer
`-log(norm(π_w)) = inertDeg(w) · log(p_w)` 条件下，逐项 q-pilot 对数也可转换到该
degree-normalized q-factor。该适配器仍属于 Scene1/Derived，不能自动替换当前
`Corollary312SourceQFactor`；在目标形式审查完成前，raw 路径和 normalized 路径必须并列
保留，避免把未决定的归一化写进 3.12。

本轮新增 `RawTargetSpecification.lean`。它把目标的 `qLogTerm` 通过显式有限
`(p,w)` grouping 绑定到 raw `Corollary312GroupedSourceQFactor`，并证明
`Corollary312` 与 raw q-sum 目标 `Corollary312RawTarget` 等价。该规格只冻结
Joshi III 目标侧的 raw q-term 表示；当前 link-place carrier 仍不是论文
`V_p^oss` 的构造，`InitialThetaData/TateFamily` 来源和 theta-volume 仍未闭合。
degree-normalized q-pilot 仍只是与 `iut` 对接的独立适配路径。
现有 `Corollary312TateQFamily` 可通过
`Corollary312RawTargetSpecification.ofTateQFamily` 自动生成这份规格；该构造器消费
已有 grouping/place compatibility，不再允许 q-family 与 raw target 提交两份脱钩的
q-log 等式。

该候选路径现在已有全局有限和消费者
`Corollary312QPilotSourceIndexBridge.absLogQ_eq_degreeNormalizedSourceQLogSum`。
它沿用现有 source-index equivalence，把 `iut` q-pilot 的 `absLogQ` 传输到
degree-normalized grouped q-family；它不修改 raw `Corollary312SourceQLogSum`，也不替
代真实 `InitialThetaData/TateFamily`、`V_p^oss` 或 uniformizer 归一化的来源义务。

这两个入口的 proof term 是有限和、对数、指数和符号的组合；它们不是从
`AdelicThetaLink` 自动生成 `Corollary312Scene1Data` 的存在定理。审计模型
`scene_adelicThetaLink_only_countermodel` 保持同一个满足全部 Prologue/Scene1 局部合约的
`sceneInput`，只把目标 `thetaVolume` 改成 `exp (4 * sceneQTerm)`，并已证明目标
`Corollary312` 失败。因此答辩中必须把“条件性对数桥已经闭合”和“真实 theta-volume、
q-family、packet/hull 账本已经构造”分开陈述；后者仍是 Scene1 的数学证明工作。

## 2. Scene2：从 Corollary 3.12 到 `abc`

### 2.1 目标链

Scene2 处理 3.12 之后的数论链：

```text
Corollary 3.12
  → theta log-volume 上界
  → different/conductor、Tate divisor 和 height 主界
  → Vojta 型不等式
  → strong abc
  → classical abc
```

这部分不得把 different、conductor 或 height 塞回 `Corollary312` 的定义。它们必须
作为 Scene2 的独立数据和命题出现，并且每个接口都有来源和证明状态。

### 2.2 条件输入的处理

Scene2 可以先定义条件性辅助定理：

```lean
theorem abc_of_cor312_and_bridge
    (h₃₁₂ : Corollary312 D)
    (hBridge : ABCBridge D) :
    ABC := by
  ...
```

这个定理只要 proof term 完整，就不含 `sorry`。但它不能被命名或文档描述为仅由
3.12 推出 `abc`。`ABCBridge` 的字段必须列出主界、height、different、conductor、
素数选择、Vojta 归约和 strong abc 翻译等实际输入。

Act1 的最终闭合还必须提供不带未证明桥接参数的公共定理：

```lean
theorem abc_of_cor312
    (h₃₁₂ : Corollary312 D) :
    ABC := by
  ...
```

如果该定理仍需要 `ABCBridge`，则 Act1Scene2 尚未闭合，Act2 不得开始。

### 2.3 Scene2 验收

- [ ] `ABC`、strong `abc`、Vojta 和主界命题均有忠实的 Lean 类型；
- [ ] 从 3.12 到 `abc` 的每个桥接步骤都有独立定理；
- [ ] 所有桥接定理均无 `sorry`、`axiom`、`admit` 或隐藏 `opaque` 证明；
- [ ] 最终 `abc_of_cor312` 不含未说明的接口参数；
- [ ] `#print axioms abc_of_cor312` 不含 `sorryAx`；
- [ ] `abc` 的整数版本、strong `abc` 和 Vojta 版本的翻译分别命名；
- [ ] 对零值、符号、本原三元组、有限素因子集和 `ε` 的边界情况有完整引理；
- [ ] Scene2 不导入 Prologue 的 `sorry` 构造子或 Act2。

## 3. Act1 总体验收

Act1 完成必须同时满足 Scene1 和 Scene2 的验收条件：

- [ ] Prologue 的载体和接口都有论文、IUT 或 mathlib 来源；
- [ ] Prologue 的所有证明缺口已列入 ledger，但没有被 Scene1/Scene2 调用；
- [ ] Scene1 的 Corollary 3.12 推导完整；
- [ ] Scene2 的 `abc` 推导完整；
- [ ] 两个场景的公共定理均不含 `sorryAx`；
- [ ] 没有通过削弱命题、改变名称或增加等价假设来消除证明义务；
- [ ] 生产者输出均被实际消费者使用，消费者需要的每个字段均可追溯到来源；
- [ ] 非退化模型、违反模型、依赖图、来源登记和许可证审计均通过。

Prologue ledger 并逐项消除已有债务，而不是继续修改 Act1 的目标命题。
