# 现有盲读回元数据合并包

`blind-readbacks.json` 合并两份已有原始读回，覆盖本单元的五个定义包。它符合当前交付模板的必需字段，并保留上一单元已接受结构的字段。

本次只组装元数据并检查文件、哈希及结构一致性。`passed: true` 只表示这些检查通过。本次没有新增独立盲读、证明验收、编译、公理审查或平台操作。

- `blind-readbacks.json`：交付数据。五个规范名称、来源链接来自当前来源台账；源文件哈希同时与实际安装文件、生成文件及包装报告核对。
- `input-manifest.json`：输入文件哈希、原始审读元数据、26 条原始输入记录的核对结果，以及已确认术语。
- `review.json`：附加编辑记录。没有修改任何英文、简体中文、日语读回，也没有修改原始覆盖清单或歧义说明。
- `source-context-references.json`：独立的来源与适配范围记录。来源叙述没有混入读回。
- `validation.json`：离线一致性检查结果及交付文件哈希。
- `originals/`：两份原始盲读回的逐字节副本；原始路径和哈希记录在输入清单中。

标题是依据实际形式声明编写的三语编辑元数据。来源台账、包装报告、负载及 Lean 文件均未提供标题字段，因此没有把标题冒称为既有规范标题。每个定义包都记录了标题来源。

第一份原始记录的字段名为 `genuinefresh_context`。交付结构将其映射到 `fresh_context`，同时保留原字段名、值、文件哈希和完整规则阅读披露。该映射不生成新的审读事实。

中文保持用户确认的“标签集”“标签集递增族”“包络”。日语保持原始读回中的通用「包絡」：实际定义没有全纯条件，不能从文件名补入「正則」条件。

所有输出都在本临时目录。没有修改主工作区文件，没有执行编译、MCP-CI、外部接口、网络或 Git 操作。

运行 `python3 validate.py` 可重新检查当前输入与交付数据。该命令只读取文件。`assemble.py` 是组装脚本，只向本临时目录写入文件。
