Its `Definitions/` files must already be integrated into the actual
`prove2me_workspace/Definitions/` paths. `prepare` requires exact equality between
the installed bytes, generated bytes and payload, wrapper report hashes, and the
reviewed source hash. It does not certify compilation. `check` requires the later
completed compilation receipts for exactly those installed files.

```bash
python3 delivery.py prepare \
```

## Ready record

`ready.template.json` enumerates the contract. It is deliberately incomplete and
fails preflight. All gate booleans, hashes, evidence lists, and receipts must refer
to the final packet and inputs. SHA256 keys for evidence are absolute paths.

The six CI gate entries each contain a nonempty list of complete MCP-CI result
JSON paths. Each receipt must have `request`, `result`, `resources`, and
`status: succeeded`. The tool checks source hashes, recorded dependency input
hashes, successful exit, actual compiler arguments, exclusive workspace mode,
snapshot absence, review verdict when task type is `review`, recorded peak
physical RSS, and the 16 GiB RSS bound for leaf jobs. It requires successful `leaf`/`file` receipts for each of
the five exact installed Definitions. Receipt resource fields and diagnostics
remain in the original files for the main agent's final resource report.

`checks_axioms` covers the owning Checks/Axioms files. The kernel gate covers
source/wrapped type and value identity, all selected declarations and generated
names, and the audited declaration map. The main agent must inspect actual
`sorryAx` and allowed-standard-axiom output; compilation success alone is not an
axiom audit. `axiom_audit` in ready records the accepted conclusion and points to
the hashed evidence through the corresponding CI gate. Complete ImportAudit,
Act1Scene1, AxiomAudit, independent blind review, SOURCE_LEDGER producer/consumer
links, and `git diff --check` evidence before delivery. Gate names are claims
reviewed by the main agent; the tool does not infer mathematical coverage from a
filename or substitute for reviewing the audit output.

## Main-agent delivery and recovery

After the existing task authorization covers these private publications, the
main agent can call:

```bash
python3 delivery.py deliver --packet /absolute/offline-packet/packet.json \
  --ready /absolute/final-ready.json --journal /absolute/delivery-journal \
  --wait-seconds 900
```

Use one journal directory for this packet for its whole lifetime. Do not delete,
copy to a fresh empty journal, or reset intent/receipt files to retry a POST. The
tool serializes invocations sharing that journal, writes and fsyncs the exact
intent before each POST, then persists the returned original job ID before any
poll. It saves a published ID before the full Definition GET. Resuming with the
same journal polls those original jobs and never submits their rows again.
Each HTTP request uses the established API loader's 45-second request timeout;
each original job has a bounded overall poll interval and five-second pacing.
A failed/errored publication stops delivery without an automatic new POST.

If a POST response is lost, intent exists without a receipt. Delivery stops.
Read your own paginated `/publish-jobs?kind=definition&limit=100&offset=...`
history to identify the original candidate job. Wait for that same job. Failure
to find a job, an HTTP timeout, or a pending job does not authorize a new POST.
When the original reaches `PUBLISHED`, supply its ID:

```bash
python3 delivery.py reconcile --packet /absolute/offline-packet/packet.json \
  --ready /absolute/final-ready.json --journal /absolute/delivery-journal \
  --name AbcAdaptation_Reference_Iut_Cor312_ThetaData_Places \
  --job-id ORIGINAL_JOB_UUID
```

Reconciliation performs only GETs. It checks the nominated job's exact code,
name, title, description, source, and private visibility. It then checks the
exact published Definition's code, metadata, ID, private visibility, and
environment before attaching the recovered receipt. The documented publish-job
schema does not include environment, so a job echo alone cannot establish it.
Pending jobs cannot be reconciled as complete; continue reading the original
job. After reconciliation, resume `deliver` with the same packet and journal.
